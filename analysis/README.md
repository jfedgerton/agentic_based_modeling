# Language model choice is a hidden assumption in agent-based simulations: replication code

Regenerates every figure and table in the manuscript and Supplementary Materials from the raw simulation runs.

## Run it

```bash
cd ~/Dropbox/ABM/paper/llm_abm_pipeline
bash run_all.sh
```

About 5 minutes on a laptop. The script runs the Python text analysis, then the R pipeline, and stops at the first
failed check. It ends by confirming that all 15 manuscript figures and tables were regenerated in this run.

Raw runs are read from `ABM_ROOT`, which defaults to two folders up (the `ABM/` folder when this repository sits at
`ABM/paper/llm_abm_pipeline/`). Elsewhere, run `ABM_ROOT=/path/to/ABM bash run_all.sh`.

## Requirements

- Python 3.9 or later, standard library only.
- R (tested with R 4.3.3) with `dplyr tidyr purrr readr tibble jsonlite nanoparquet ggplot2 patchwork scales ggalluvial
  RColorBrewer`. `run_all.R` checks for them and prints the install command if any are missing. The versions used
  are written to `logs/sessionInfo.txt` on every run.
- Randomness (permutation tests, bootstraps, jitter, the validation sample) uses seed 123.

## Exclusions (`R/01_run_index.R`)

A run is dropped from analysis if any of these holds, and `derived/run_index.csv` records which:

1. More than 5% of its LLM calls failed to parse (all DeepSeek crisis-game runs and both text-signal runs).
2. It is a rule-based benchmark whose game settings differ from the LLM runs it is compared with (the crisis-game
   classic run with bluffing disabled; every LLM crisis-game run has bluffing enabled).
3. It is a byte-identical replay of another run of the same arm (the 18 prisoner's dilemma and civil violence runs in
   `one_simulation/`, which repeat five-seed runs with seeds 42, 52 and 62).

107 run folders, 89 distinct runs, 24 excluded.

## Definitions

- Steady state: mean over steps 51-100 of a 100-step run (`STEADY_STATE_STEPS` in `R/00_config.R`). Every reported
  quantity uses this window, including the decision rules (`R/07`) and the threshold recovery (`R/03`).
- Deviation (text analysis): a decision where the LLM agent's action differs from the classic rule's action in the
  same state. Prisoner's dilemma, any cooperation. Civil violence, active if and only if G - N > 0.1, computed from
  the values printed in the agent's prompt. Decisions whose response failed to parse are skipped, because the logged
  action is the classic fallback. See `python/CODEBOOK.md` for the reason categories and rules. Each waffle cell
  shows only its dominant direction (e.g. quiet where the classic rule is active), so its label and n describe exactly
  the decisions shown; 57 opposite-direction decisions (under 1% of any cell) are dropped and listed in
  `logs/text_analysis.log`.
- Validation: `python/validation/validation_blind.csv` (375 items, seed 123) is for hand coding and is not redrawn by
  `run_all.sh`; machine labels are in `validation_key.csv`. After a codebook change, refresh the machine labels without
  redrawing with `python3 python/04_validation_sample.py derived/text/deviation_labels.csv.gz python/validation --rekey`.

## Known limits

- Crisis game, calculator signal labels. The calculator prompt offers S1 (low value_a) to S3 (high), but the simulation
  code at v1.0-experiments stores S1 as STRONG and S3 as WEAK. Prompts shown to other agents reverse the same mapping,
  so agents saw the labels that were chosen, and war frequency and payoffs are unaffected. The logged bluff_rate and
  bluff_success_rate are not: `R/04` recomputes both from `dyads.parquet` by signal meaning (logged 0.19, corrected
  about 0.70 for the calculator), after checking that the same code with the stored labels reproduces every logged
  value. Two residual effects cannot be fixed without new runs: calculator calls that fail to parse fall back to the
  classic rule, which reads the stored labels and so treats a high signal as weak, and a fallback signal is shown to
  neighbors on the reversed scale. Both affect only calculator calls that failed to parse (2.1% of all calculator calls; 3.6% of its signal calls in steps 51-100).
- Crisis game: one run per arm, so no seed-level uncertainty. `table_ic.tex` reports the range of per-step values
  over steps 51-100, which describes within-run fluctuation only.
- Prisoner's dilemma GPT agents give only 25 (calculator), 1 (reasoner) and 28 (role-player) distinct rationales per
  run over steps 51-100 (temperature 0, cached prompts), so decision counts there are state-weighted replays, not
  independent choices.
- Figures are written with `cairo_pdf` when R has Cairo and with `pdf()` otherwise (`PDF_DEVICE` in `R/00_config.R`).
